# C2.1 Board Pins, Active Levels, Pulls, Electrical Capabilities and Revision Detection

## Purpose

C2.1 defines the authoritative board-specific contract for
`components/board`.

The completion criterion is:

> All board-specific data is isolated in the board-support component.

The accepted C1 architecture requires:

- `components/board` is the sole board-support component.
- Public board symbols use the `sqd_board_*` namespace.
- No separate `bsp` component or board-support directory is introduced.
- Board-specific facts do not appear in product, platform,
  device-driver or generic-HAL implementation code.
- The board component has no dependency on another SQD component.
- Raw GPIO numbers do not escape above the hardware-abstraction boundary.

This document defines logical board signals, private GPIO mappings,
active states, external conditioning, safe states, electrical limits
and revision-selection behavior.

Startup sequencing and hardware self-test implementation remain assigned
to C2.2 and C2.3.

## Source and evidence hierarchy

Board facts use this authority order:

1. Exact Heltec WiFi LoRa 32 V3.2 reference schematic.
2. Official Heltec V3.2 pin map and product document.
3. ESP32-S3 and peripheral manufacturer datasheets.
4. Physical-board marking, measurements and hardware tests.
5. Framework or tool output.
6. Community material only as a non-authoritative lead.

A fact is **documentation-verified** when supported by an exact official
schematic, official pin map or manufacturer datasheet.

A fact is **hardware-verified** only when reproduced on the controlled
physical board with retained evidence.

## Pull and conditioning contrac

| Signal | External board condition |
|---|---|
| OLED SDA | 10 kΩ pull-up to Vext |
| OLED SCL | 10 kΩ pull-up to Vext |
| User button / GPIO0 | 10 kΩ pull-up to 3.3 V |
| LoRa NSS | 10 kΩ pull-up to 3.3 V |
| LoRa reset | 10 kΩ pull-up to 3.3 V |
| Vext control | 100 kΩ pull-up to 3.3 V |
| Battery divider | 390 kΩ upper resistor and 100 kΩ lower resistor |
| User LED | 330 Ω series resistor |

Internal ESP32-S3 pulls must not be treated as replacements for these
board components.

Where no external pull is shown, firmware must not enable an internal
pull without a documented electrical reason.

## Battery measurement contrac

The battery divider is disconnected unless
`SQD_BOARD_SIGNAL_BATTERY_ADC_CONTROL` is driven high.

The nominal divider relationship is:

```tex
VADC = VBAT × 100 kΩ / (390 kΩ + 100 kΩ)
VBAT = VADC × 4.9


A battery measurement operation shall:

1. Configure the battery ADC control as an output low.
2. Configure GPIO1 as the controlled ADC input.
3. Drive the battery ADC control high.
4. Wait for the C2.2-defined settling interval.
5. Acquire calibrated ADC samples.
6. Drive the battery ADC control low.
7. Report raw ADC, calibrated voltage and calculated battery voltage.

The divider must not remain enabled continuously without a recorded
power-budget decision.

## GPIO0 boot-strap constrain

GPIO0 is both the user button and an ESP32-S3 boot-mode strapping pin.

- GPIO0 shall be configured only as an input.
- The external 10 kΩ pull-up preserves the normal high strap value.
- Pressing the button during reset may select download mode.
- No firmware-controlled output may drive GPIO0.
- Button debouncing must not change the GPIO direction.

## Restricted and conditionally reserved pins

| GPIO or group | Restriction |
|---|---|
| GPIO3 | JTAG-source strapping pin; explicit review required before assignment |
| GPIO45 | VDD_SPI-voltage strapping pin; explicit review required before assignment |
| GPIO46 | Boot-mode and ROM-message strapping pin; explicit review required before assignment |
| GPIO19 and GPIO20 | Native USB D-/D+ capable; preserve pending service-interface decision |
| GPIO39 through GPIO42 | JTAG-capable pins; assignment requires a debug-access decision |
| CHIP_PU / RST | Hardware reset input; not an application GPIO |

## Electrical capabilities and limits

The board logic domain is 3.3 V.

ESP32-S3 electrical-current values are limits, not normal design targets:

- High-level source current is 40 mA typical under the datasheet test condition.
- Low-level sink current is 28 mA typical under the datasheet test condition.
- These values are not symmetric 40 mA source-and-sink guarantees.
- Internal weak pull-up and pull-down resistors are approximately 45 kΩ typical.
- GPIO drive strength must be selected for the connected load, edge rate and power budget.

The official board documentation publishes these connector ratings:

| Output | Published rating |
|---|---:|
| 3.3 V header output | 500 mA |
| 5 V header output when USB-powered | 500 mA |
| Vext output | 350 mA |

Published ratings are ceilings, not the SQD application power budget.

## Required safe board state

Before revision validation succeeds and before any device driver starts,
the board component shall establish or preserve these states:

| Signal | Required safe state |
|---|---|
| Vext control | High; Vext disabled |
| Battery ADC control | Low; divider disconnected |
| User LED | Low; LED off |
| LoRa NSS | High; radio deselected |
| LoRa reset | High; reset deasserted |
| OLED reset | Low until Vext is enabled and stable |
| OLED SDA and SCL | Released open-drain |
| User button | Input only |
| LoRa BUSY, DIO1 and MISO | Inputs |
| UART0 RX | Input |

An unsupported or unknown revision must never enable Vext, enable the
battery divider, select the LoRa device or illuminate the user LED.

C2.2 shall define the deterministic transition from reset defaults to
this safe state and then to each initialized peripheral state.

## Revision-selection strategy

The V3.2 reference design exposes no dedicated hardware revision-ID
resistor, EEPROM or revision strap that firmware can reliably probe.

Board revision selection is therefore compile-time controlled.

```c
typedef enum {
    SQD_BOARD_REVISION_UNKNOWN = 0,
    SQD_BOARD_REVISION_HELTEC_WIFI_LORA_32_V3_2 = 1
} sqd_board_revision_t;


The build configuration shall use a closed Kconfig choice.

The only currently supported deployable selection is:

```tex
CONFIG_SQD_BOARD_HELTEC_WIFI_LORA_32_V3_2=y


There shall be no silent default that converts a missing selection
into Heltec V3.2 support.

The configured compatibility ID shall be recorded in build metadata.
The board component shall not depend on diagnostics or build metadata.

## Unknown and invalid revision policy

### Build-time invalid state

The build shall fail when:

- No supported board revision is selected.
- More than one board revision is selected.
- The selected revision has no complete mapping table.
- The compatibility ID does not match the selected revision.

Kconfig constraints and compile-time assertions shall enforce these rules.

### Runtime unknown state

`SQD_BOARD_REVISION_UNKNOWN` is an internal sentinel, not a deployable
configuration.

If revision state is unknown or corrupt at runtime:

1. Board initialization returns `SQD_STATUS_NOT_SUPPORTED` or
   `SQD_STATUS_INTEGRITY`, as applicable.
2. All outputs remain in the required safe board state.
3. Peripheral initialization does not continue.
4. No automatic fallback to V3.2 mappings occurs.
5. The failure is propagated to the startup-policy owner.

Firmware cannot automatically prove that the physical PCB is V3.2.
Replacing the board requires physical revision identification, build
configuration review and repetition of applicable C2.3 tests.

## C2.2 implementation handoff

C2.2 shall implement:

- Private logical-signal-to-GPIO mapping inside `components/board`.
- Safe output preparation before peripheral enable.
- Active-low Vext control.
- Active-high battery-divider control.
- OLED power and reset ordering.
- LoRa NSS and reset preparation.
- GPIO0 input-only enforcement.
- Revision validation before board activation.
- Failure rollback to the required safe board state.

C2.2 shall not copy raw GPIO literals into HAL, device-driver,
platform or product code.

## C2.3 board self-test preview

| Check | Required evidence |
|---|---|
| Revision selection | Configured revision and compatibility ID reported |
| User LED | Off/on/off transition observed |
| User button | High unpressed and low pressed without direction change |
| OLED | I2C acknowledgement and controlled reset verified |
| Vext | Disabled and enabled states verified |
| Battery ADC | Enable, settle, sample, scale and disable verified |
| LoRa SPI | NSS, reset, BUSY, DIO1 and communication verified |
| UART0 | CP2102 console communication verified |
| Safe-state recovery | Abort or failure restores safe outputs |

No signal is recorded as hardware-verified until retained C2.3
evidence exists.

## Ownership and dependency boundary

`components/board` owns:

- Board-revision selection and validation state.
- Logical board-signal definitions.
- Private numeric GPIO mappings.
- Active-state and board-conditioning facts.
- Safe board preparation.
- Board-level self-test coordination.

`components/board` does not own:

- Generic peripheral handles or bus locks; these belong to HAL.
- Device protocol state; this belongs to device drivers.
- Product retry, recovery or authorization policy.
- Diagnostic storage or logging infrastructure.
- Build-metadata storage.

The board component has no SQD component dependency.

## C2.1 acceptance criteria

C2.1 is ready for acceptance when:

1. Exact V3.2 board identity is linked to retained physical evidence.
2. Every used board signal has one logical identity and GPIO mapping.
3. GPIO35 user LED and GPIO37 battery control are included.
4. Direction, active state, conditioning and safe state are defined.
5. Strap, USB and debug-sensitive pins are controlled.
6. Electrical-current statements match the ESP32-S3 datasheet.
7. Battery-divider control and conversion are explicit.
8. Unknown and invalid revision states fail closed.
9. No obsolete `bsp` component or API identity remains.
10. Public naming uses the `sqd_board_*` namespace.
11. Raw GPIO numbers remain isolated in `components/board`.
12. C2.2 and C2.3 handoff requirements are explicit.
13. Static document verification passes.
14. Pull-request and post-merge verification pass.
