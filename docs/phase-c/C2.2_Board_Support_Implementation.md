# C2.2 Board Support Implementation

## Purpose

C2.2 implements the board-owned runtime boundary defined by C2.1
for the exact Heltec WiFi LoRa 32 V3.2 HTIT-WB32LAF board.

The implementation provides:

- A public sqd_board API using sqd_status_t.
- A private logical-signal-to-GPIO mapping.
- Deterministic fail-closed GPIO preparation.
- Explicit compile-time board selection.
- Runtime revision validation.
- Safe-state rollback after GPIO failures.

Physical signal validation remains assigned to C2.3.

|---|---|
| Product | Heltec WiFi LoRa 32 V3.2 |
| Reference design | HTIT-WB32LAF_V3.2 |
| MCU | ESP32-S3FN8 |
| Flash | 8 MB |
| Compatibility ID | heltec-wifi-lora-32-v3.2-htit-wb32laf |

| Build selection | CONFIG_SQD_BOARD_HELTEC_WIFI_LORA_32_V3_2=y |

No V3, V3.1, V4 or generic Heltec fallback is implemented.

## Public and private boundary

The public header is components/board/include/sqd_board.h.

The public API returns sqd_status_t and does not expose:

- esp_err_t
- gpio_num_t
- GPIO_NUM values
- driver/gpio.h
- SQD_BOARD_SIGNAL private identifiers

ESP-IDF GPIO types and raw mappings remain private.

## Public API

| Function | Contract |
|---|---|
| sqd_board_prepare_safe_state | Establish fail-closed GPIO states and clear runtime revision state. |

| sqd_board_set_vext_enabled | Control the active-low Vext rail after initialization. |
| sqd_board_set_battery_measurement_enabled | Control the active-high battery divider after initialization. |

## Required safe board state

- Vext control remains high and Vext remains disabled.
- Battery ADC control remains low and the divider remains disabled.
- The user LED remains low and off.
- LoRa NSS remains high and deselected.
- LoRa reset remains high and deasserted.
- OLED reset remains low and asserted.
- OLED SDA and SCL remain released high in open-drain mode.
- GPIO0 remains input-only with its pull-up enabled.
- Battery ADC, LoRa inputs and UART0 RX remain inputs.

For every board-owned output, gpio_set_level establishes the
required level before gpio_config enables the output direction.

Successful initialization retains Vext disabled, the battery
divider disabled and the user LED off.

## Runtime failure policy

Runtime setters return SQD_STATUS_INVALID_STATE before successful
board initialization.

A board-owned GPIO failure causes the component to:

1. Reapply the required safe board state.
2. Clear the initialized flag.
3. Restore SQD_BOARD_REVISION_UNKNOWN.
4. Return the translated failure status.

An unknown selected revision returns SQD_STATUS_NOT_SUPPORTED.
An invalid map or inconsistent revision returns SQD_STATUS_INTEGRITY.

## ESP-IDF requirement-discovery behavior

ESP-IDF evaluates component CMake files once in script mode to discover component dependencies before the final generated Kconfig values are available.

The C2.2 board-selection assertion is therefore skipped only when CMAKE_SCRIPT_MODE_FILE is active. During normal project configuration, exactly one controlled SQD board selection remains mandatory and a missing or unknown selection still fails closed.

## C2.3 boundary

Static verification and compilation do not establish physical
hardware conformance.

C2.3 remains responsible for physical evidence covering the LED,
button, OLED, Vext, battery measurement, LoRa, UART0 and safe-state
recovery behavior.
