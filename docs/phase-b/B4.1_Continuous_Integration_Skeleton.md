# B4.1 Continuous-Integration Skeleton

## Purpose

B4.1 establishes the initial controlled continuous-integration pipeline
for the SQD ESP32-S3 firmware repository.

The pipeline validates pull requests and pushes to main using formatting
checks, CI-tool validation, host tests and controlled ESP-IDF builds.

## Acceptance criteria

B4.1 is accepted when:

1. The workflow is committed.
2. Pull requests receive automated results.
3. Formatting violations fail the pipeline.
4. The pinned Clang-Tidy executable and configuration are validated.
5. Host-side tests execute automatically.
6. Debug, validation and production profiles build through B3.2.
7. The first complete GitHub Actions pipeline passes.

The final pipeline-run acceptance item remains pending until the
committed workflow executes on GitHub.

## Quality job

The Ubuntu quality job performs:

- Pinned CI dependency installation.
- Workflow-contract validation.
- C and C++ formatting verification.
- Clang-Tidy executable and configuration verification.
- Host-side CI tests.

Controlled CI versions:

- Clang-Format 22.1.8
- Clang-Tidy 22.1.8
- PyYAML 6.0.3

## Static-analysis scope

B4.1 validates the Clang-Tidy executable, configuration and
compilation-database processing contract.

Full ESP-IDF translation-unit analysis is not claimed by B4.1.
It requires a separately controlled ESP-Clang integration.

## Profile-build matrix

The Windows build matrix contains:

- debug
- validation
- production

Each profile executes through tools/ci/run_profile_build.ps1.
The wrapper preserves the existing B3.2 controlled-build contract.

The temporary worktree uses the historical compatibility branch:

- feat/b3.2-controlled-tooling

The tested source commit is not rewritten.

## Configuration control

Each profile uses:

- sdkconfig.defaults
- sdkconfig.defaults.<profile>

The developer-local root sdkconfig is generated and is not an
authoritative CI input.

## Evidence

Per-profile evidence is collected under:

- artifacts/b4.1/profile-build/<profile>/

GitHub Actions uploads each profile directory with 14-day retention.
Formal artifact-archive acceptance is owned by B4.2.
